# Reading Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Reading tab that classifies the vault's notes by Roadmap topic, suggests what to read next, lets Khue read a note on the web, quizzes them (3 open questions, one Claude call to grade), schedules rechecks (7 → 21 → done, fail → 2 days) and shows due rechecks in Today.

**Architecture:** Pure logic (schedule, ordering) in `src/lib/reading*.ts` so server and UI share it. A `server/reading/` module owns the catalog scan, the Claude prompts and the reading service, and stores everything in `state.json` under `reading`. The vault is only read. `server/api.ts` gets `/api/reading/*` routes plus an image route, and the overview's Today list gains a `reading` array.

**Tech Stack:** as the base app (Node 22, React 18, TS, Vite, vitest). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-24-reading-design.md` (base: `2026-10-22-tutor-learner-design.md`).

## Global Constraints

- Reading never writes to the vault. All reading data lives in `state.json` → `reading`, `today.reading`, `settings.readingReviewsPerDay`.
- Catalog: every `.md` in the vault except under `Tutor/`, `.claude/`, `.obsidian/`, `.git/`, `.trash/`, `node_modules/`, and except notes longer than 60,000 characters.
- Classification: batches of 10 notes, each with title, path and the first 1,500 characters. `topic` must be a name from `topic_order`, otherwise `null`. `priority`: `high` | `medium` | `low` | `skip`.
- Quiz: 3 open questions, codes `r1`, `r2`, `r3`, 2–4 criteria each, built from at most 60,000 characters of the note. Grading: one Claude call for all 3. Pass = at least 2 of 3 correct.
- Schedule: rung = consecutive passes since the last failure; 1 → +7 days, 2 → +21 days, 3 → `done`; failure → +2 days, rung 0. Dates are capped at `interview_date - interview_buffer_days` (if the cap is before today, use today), same as `tutor.py`.
- Today: at most `settings.readingReviewsPerDay` (default 3, allowed 0–10) due notes, locked for the day, ordered by most overdue, then priority, then path. They count in "N / M done". Unread notes never enter Today.
- Up next: 3 notes; groups = topics of today's points, then studied topics in `topic_order`, then the rest in `topic_order`; inside a group: priority, non-source first, shorter first, path.
- Answers are saved before grading. Claude errors keep the check `pending` with `error`; they never count as a failure. One appeal per failed check.
- Image route: only `png|jpg|jpeg|gif|webp|svg` files whose realpath is inside the vault; SVG is sent with `Content-Security-Policy: sandbox`.
- UI and content language as the base app: UI labels in English; prompts ask for simple English.

## Review Focus

1. **Note edited after its quiz was made** → the next check uses a new quiz, history and rung are kept. Test: Task 4 `regenerates the quiz when the note changed and keeps the rung`.
2. **Note deleted or grown past 60K** → hidden from every list, progress kept, comes back if the note returns. Test: Task 2 `drops long and missing notes but keeps progress` (service) and Task 1 `skips long notes`.
3. **Classification stops on a usage limit** → finished batches are kept, the run can continue later, no batch is lost. Test: Task 4 `classify stops on limit and resumes`.
4. **Interview cap already passed** → next check is today, not in the past, never after the interview. Test: Task 1 `caps at the interview and uses today when the cap passed`.
5. **Image path tricks** (`..`, absolute, symlink out, `.md` file) → 404, never a file outside the vault. Test: Task 3 `refuses paths outside the vault and non-images`.

## Shared types (add to `src/lib/types.ts` in Task 1)

```ts
export type ReadingPriority = 'high' | 'medium' | 'low' | 'skip'
export interface CatalogEntry { path: string; title: string; chars: number; mtime: number; hash: string
  topic?: string | null; priority?: ReadingPriority; minutes?: number; why?: string; classifiedHash?: string; isSource: boolean; present: boolean }
export interface ReadingQuiz { hash: string; questions: Question[] }          // kind 'open', q r1..r3
export interface ReadingResult { q: string; ok: boolean; why: string; missing: string[]; feedback: string }
export interface ReadingCheck { id: string; date: string; kind: 'first' | 'recheck'; quizHash: string; answers: Record<string, string>
  state: 'pending' | 'graded'; results?: ReadingResult[]; english?: Record<string, EnglishNotes>; passed?: boolean
  appealed?: boolean; appeal?: string; error?: { code: 'limit' | 'auth' | 'failed'; message: string } }
export interface ReadingProgress { skipped?: boolean; checks: ReadingCheck[] }
export type ReadingStatus = 'unread' | 'understood' | 'reread' | 'done'
export interface ReadingState { catalog: Record<string, CatalogEntry>; quizzes: Record<string, ReadingQuiz>; progress: Record<string, ReadingProgress> }
export interface ReadingItem extends CatalogEntry { status: ReadingStatus; skipped: boolean; nextCheck: string | null; rung: number; openCheck: ReadingCheck | null }
export interface ReadingOverview { items: ReadingItem[]; upNext: string[]; due: string[]; classify: { total: number; done: number; running: boolean; error: string | null } }
```

Also: `TodayList` gets `reading: string[]` (old saved lists without it read as `[]`); `Settings` gets `readingReviewsPerDay: number` (default 3); `AppState` gets `reading: ReadingState` (default empty); `Overview` gets `reading: Record<string, { title: string; topic: string | null; done: boolean; kind: 'recheck' | 'reread' }>` for the locked Today notes.

### Task 1: Pure reading logic

**Files:** Create `src/lib/readingSchedule.ts`, `src/lib/readingOrder.ts`, tests beside them. Modify `src/lib/types.ts`.

**Interfaces — Produces:**
- `deriveReading(checks: ReadingCheck[], today: string, cap: string | null): { status: ReadingStatus; rung: number; nextCheck: string | null }` — uses graded checks only (final `passed`), in order. No graded check → `unread`, `nextCheck: null`. Last graded failed → `reread`, next = last date + 2. Rung 3 → `done`, `nextCheck: null`. Else `understood`, next = last date + (rung 1 ? 7 : 21). Cap: next = min(next, cap); if cap < today, next = today.
- `interviewCap(config: TutorConfig): string | null` (interview_date − buffer days).
- `upNext(items: ReadingItem[], todayTopics: string[], studiedTopics: string[], topicOrder: string[], n = 3): string[]` — only `status === 'unread'`, not skipped, `present`, `topic` set, `priority` not `skip`.
- `dueReading(items: ReadingItem[], today: string): string[]` — present items with `nextCheck <= today` and status `understood` or `reread`, ordered most overdue, then priority, then path.

### Task 4: Prompts and reading service

**Files:** Create `server/reading/prompts.ts`, `server/reading/service.ts`, `server/reading/service.test.ts`, `server/reading/prompts.test.ts`. Modify `server/state.ts` (default `reading`, `settings.readingReviewsPerDay`, `today.reading` read as `[]` when missing).

**Interfaces — Produces:**
- prompts: `CLASSIFY_SCHEMA` → `{ notes: Array<{ path, topic: string|null, priority, minutes: integer, why }> }`; `buildClassifyPrompt(notes: Array<{ path; title; head }>, topics: string[]): string`; `READING_QUIZ_SCHEMA` → `{ questions: Question[] }`; `buildReadingQuizPrompt(title: string, text: string): string`; `validateReadingQuiz(raw): Question[]` (3 open questions, 2–4 criteria, renumbered `r1..r3`, else `ClaudeError('failed')`); `READING_GRADE_SCHEMA` → `{ results: ReadingResult[]; english: Array<{ q; corrected; notes }> | null }`; `buildReadingGradePrompt(a: { title; text; questions; answers; english: boolean; appeal?: string }): string`.
- `createReadingService(deps: { vault; tutor: TutorCli; store: StateStore; claude; today: () => string; newId?: () => string }): ReadingService` with:
  - `sync(): Promise<void>` — scan + merge into `state.reading.catalog` (sources from the tutor export).
  - `overview(): Promise<ReadingOverview>` — sync first (cheap: mtime + size check before hashing), build items with `deriveReading`, `upNext` with today's point topics (from `state.today`) and studied topics (export points not `new`), `due`, classify progress.
  - `classifyPending(): Promise<void>` — background single runner; batches of 10 present entries whose `classifiedHash !== hash`; saves each batch; on `ClaudeError` `limit`/`auth` stop and record `error`; on `failed` skip that batch for this run.
  - `reclassify(path: string | 'all'): Promise<void>` — clears `classifiedHash` (one note or all) then runs `classifyPending`.
  - `note(path): Promise<{ markdown: string; entry: CatalogEntry }>`.
  - `quiz(path): Promise<ReadingQuiz>` — reuse when `quiz.hash === entry.hash`, else generate (one Claude call) and save.
  - `submit(path, answers: Record<string,string>): Promise<ReadingCheck>` — needs a quiz with the current hash and an answer for every question; refuse while an open (pending) check exists or another call for the path runs (`StudyError('bad-state')`); `kind` = `first` if no graded check else `recheck`; save `pending` first; grade in one call; `passed = results.filter(ok).length >= 2`; Claude error → stays `pending` with `error`.
  - `retry(path, id)`, `appeal(path, id, reason)` (only graded, failed, not appealed; regrade once; final result replaces `results`/`passed`), `skip(path, skipped: boolean)`.
  - `todayReading(date, cap: number): Promise<string[]>` — `dueReading` first `cap` items.
